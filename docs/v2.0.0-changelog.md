# LiteQSL-Web v2.0.0 版本发布说明

**发布日期：** 2026-09-13
**版本号：** v2.0.0

---

## 版本概述

v2.0.0 是一次**后端整体重写**：将服务端从 Python + FastAPI + Uvicorn 迁移为 **Go + SQLite 单体程序**。

重构目标不是“重做一个类似项目”，而是**在完全保留现有功能、数据与前端的前提下**去掉 Python 运行环境依赖：

```text
v1.x：Python 环境 → pip/pyenv/虚拟环境 → uvicorn 启动
v2.0：下载 → 修改配置 → ./liteqsl → 完成
```

前端 HTML/CSS/JavaScript **零改动**，数据库结构与数据**零迁移**。

---

## 主要更新

### 1. 后端重写为 Go

| 方面 | v1.3.0 | v2.0.0 |
|------|--------|--------|
| 运行时 | Python 3.10+ / FastAPI / Uvicorn | 单二进制（无需运行时） |
| 数据库驱动 | aiosqlite | `modernc.org/sqlite`（纯 Go，无 CGO） |
| HTTP | FastAPI + Starlette | 标准库 `net/http` |
| 依赖安装 | `pip install -r requirements.txt` | 无 |
| 部署产物 | 源码 + 虚拟环境 | 单个可执行文件（约 11–12 MB） |

服务器无需再安装 Python、pip、pyenv 或虚拟环境。

### 2. 数据库完全兼容（零迁移）

- 沿用**完全相同的**表结构：`logs`、`users`、`settings`、`schema_version`。
- 复用 `schema_version` 迁移表（版本 1、2 保持不变），**不会重复执行迁移**。
- 旧库中的 bcrypt `$2b$` 密码哈希可直接校验（已验证），旧 SHA-256 哈希在登录时自动升级。
- 升级后**可原地回滚**到 v1.x。

### 3. API 完全兼容

- 前端**零改动**；路径、方法、参数、JSON 字段名、错误体 `{"detail": ...}`、状态码全部保持一致。
- 已与 Python 原版做逐字段响应比对：**26 项检查全部通过**（含 CSV 导出字节级一致）。
- 详细对照见 [`rebuild_reports/api-compatibility.md`](rebuild_reports/api-compatibility.md)。

### 4. 多平台发布

提供 Linux（amd64 / arm64 / arm）、Windows（amd64）、macOS（amd64 / arm64）二进制与发布包。

### 5. 新增 `reset-password` 子命令

替代 v1.x 的 `reset_password.py`：

```bash
./liteqsl reset-password --list              # 列出账户
./liteqsl reset-password                     # admin → Admin123! 并重置首次登录状态
./liteqsl reset-password <用户名> <新密码>     # 重置指定用户
```

### 6. 部署脚本与文档

- `deploy.sh` 重写为 Go 版：停止 → 取二进制（下载/构建）→ 准备布局 → 启动；支持 systemd 与守护循环。
- `scripts/build-release.sh`：一键交叉编译 + 打包发布包。
- `deploy/liteqsl.service`：systemd 单元（含安全加固）。
- 新增 [`rebuild_reports/deployment.md`](rebuild_reports/deployment.md) 部署指南。

### 7. 前端离线化与修正

- **Chart.js 本地化**：由 CDN 改为 `static/js/vendor/chart.umd.min.js`，内网/离线部署图表可正常渲染（Tailwind 此前已本地化）。
- **批量状态下拉补全**：补齐缺失的「已收到」选项（后端本就支持 6 种 QSL 状态）。
- **页脚技术与版本号更正**：页脚标注由 “Powered by FastAPI + SQLite” 更正为
  “Powered by Go + SQLite”；版本号改为从 `/health` 动态读取并显示，避免在 HTML 中硬编码导致过期。
- **首次登录强制改密加固**：进入管理后台时**先**校验首次登录状态；未完成改密前不加载任何数据、
  不初始化其他模块，弹窗无法跳过。后端对全部管理接口返回 `403 请先完成首次登录凭据修改` 作为兜底。

## 升级注意事项

1. **升级前先备份**：管理后台「备份数据库」下载，或复制整个 `data/` 目录。
2. 停止 v1.x 服务（`systemctl stop liteqsl-web` 或 `./deploy.sh stop`）。
3. 放置 v2 的 `liteqsl` 二进制与 `static/`（保持 `static/` 与二进制同目录）。
4. 创建 `config.yaml`（可从 `config.example.yaml` 复制；不创建则使用内置默认值）。
5. 启动 `./liteqsl`，访问 `/health` 确认版本为 `2.0.0`。
6. **重新登录一次**（会话格式不同，属预期行为）。

> v2 仓库不再包含 Python 源码。如需回滚，可从 Git 历史的 v1.x 标签/提交中取得。

## 已知限制

1. **单管理员账户**：不包含多用户权限系统（与 v1.x 相同）。
2. `AppVersion` 变更会影响 ADIF 导出中的 `PROGRAMVERSION` 字段。
3. 公开接口会返回日志数据，请按部署场景判断是否适合公网开放。
